## Findings and limits

1. **Suspend/resume notification registration failed.** At
   `2026-11-08T13:08:17.259725700Z`, the supervisor logged
   `no suspend/resume notifications: WIN32_ERROR(87)` from
   `supervisor/src/presence.rs:341`. This is a separate Windows presence/scheduling
   follow-up; this run did not suspend the guest or establish the downstream
   effect. The same startup logged that the stop-shortcut listener was active,
   and the global stop test passed.
2. **Initial config window extended behind the taskbar.** At this resolution,
   Launch was partly obscured until maximizing the config window. Maximized UI
   was usable throughout the test. This merits a smaller-screen window sizing
   check.
3. **Stable screenshots can precede readiness.** A first capture after upload or
   launch sometimes showed the unchanged loading state; another capture showed
   the completed transition. `vmctl wait` does not prove the app has finished.
4. **Storage is tight.** Guest free space after the builds was 5,056,737,280 bytes
   (about 4.7 GiB). Host `disk.qcow2` occupied about 75.2 GiB for a 64 GiB guest
   disk with two internal snapshots. Avoid more snapshots until storage is
   addressed; no compaction was attempted.
   Saved RAM is held separately in `OVMF_VARS.qcow2`, occupying another 9.2 GB.
5. **Host memory pressure interrupted teardown.** The kernel OOM killer killed
   QEMU (`windows-11`, PID 222241) at 13:18:02, after the UI checks passed.
   This was a host resource failure, not an engine crash. The 6 GB VM still
   needs less concurrent host load or a smaller RAM allocation before another
   run. The guest was not restarted under the same memory pressure.
6. **Post-kill disk metadata recovery completed.** A read-only main-disk check
   returned 1,558 reference-count/flag errors and five leaked clusters. Before
   repair, a Btrfs reflink backup was preserved at
   `~/Machines/windows-11/disk.pre-repair-2026-11-08.qcow2`. The destination needed
   the same no-COW attribute as the source for cloning to work. Offline
   `qemu-img check -r all` fixed 779 underlying reference-count issues and five
   leaks. A second read-only check exited successfully with no errors or leaks;
   both internal snapshots remained listed. This verifies qcow2 metadata, not
   the guest filesystem. No post-repair Windows boot was attempted. A separate
   read-only firmware-image check reported no corruptions and 133 leaks;
   firmware-image metadata was not modified.

This pass does not cover image/video/audio decoding, wallpaper restoration,
links, notifications, scheduling triggers, screen locking, suspend/resume,
installer/update flows, the gpui apps, or hardware GPU rendering. The next
functional pass should use a synthetic media pack for image/video/audio and
wallpaper checks, and investigate the Windows presence registration failure.
